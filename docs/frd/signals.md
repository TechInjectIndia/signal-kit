# Signal delivery and instrumentation FRD

Implementation baseline for the founder's 2026-10-05 build instruction. Detailed defaults are engineering choices; no independent approval of this file is claimed.
Sources: [PRD](../PRD.md), [architecture](../ARCHITECTURE.md).

## Event flow

Hosts emit 17 predefined typed events (`page_view`, `product_view`, `add_to_cart`, `remove_from_cart`, `view_cart`, `begin_checkout`, `add_shipping_info`, `add_payment_info`, `purchase`, `refund`, `view_item_list`, `select_item`, `add_to_wishlist`, `generate_lead`, `search`, `sign_up`, `login`) and consumer events registered once in the root SDK configuration. `phone_click`, `whatsapp_click` and generic `custom_event` are example-owned definitions, unavailable unless explicitly registered. Schemas validate currency, finite nonnegative value, bounded item lists, positive quantity, and purchase transaction ID. Cart, checkout, list and purchase events require at least one item; `product_view` may use an empty item list and `refund` may omit items. Optional host-supplied `checkout_id`, `payment_attempt_id` and `customer_type` (`guest` or `registered`) and item `index`, `item_list_id` and `item_list_name` pass through on the events that declare them; the SDK never generates them. Identifier fields (`item_id`, `transaction_id`, `checkout_id`, `payment_attempt_id`, `item_list_id`, Meta `order_id` and `content_ids`) skip the bare-digit phone heuristic but still reject email-like values, a leading `+`, whitespace or parentheses and dotted or dashed phone formats. The deprecated single-item `product_view` shape is normalised to `items[]` before any provider sees it. Contact events allow only a non-identifying `channel` (`phone` or `whatsapp`), never phone numbers or destinations. Raw user IDs are not event properties; an opaque host user key travels through `setUser`, not event fields. Unknown fields are stripped at runtime. Each provider receives its own cloned safe payload. Caller event ID survives browser/server copies and retry; otherwise generate UUID. Transaction, event and trace IDs are independent.

Consent categories analytics, marketing and observability default false. Drop denied events; never queue for later replay. Withdrawal aborts supported pending transports, invokes provider consent hooks, and prevents future dispatch. Data already accepted by a provider cannot be retracted. Host must supply and persist real consent; SDK is not a consent-management platform.

GA4 Consent Mode mapping: the owner confirmed on 12 November 2026 that marketing consent may authorize all three Google ad fields. To preserve existing hosts' consent scope, this mapping requires an explicit opt-in. Before measurement, the browser adapter defaults `analytics_storage`, `ad_storage`, `ad_user_data` and `ad_personalization` to denied. By default it updates only `analytics_storage` when the host's analytics choice changes; `marketing: true` does not make this adapter grant Google ad fields. A host may configure `createGA4Provider({ measurementId, googleAdsConsent: 'marketing' })` to make marketing consent control all three Google ad fields together. Only hosts whose marketing choice covers Google ad storage, user data and personalization should enable this option. After initialization, consent changes update the effective fields, and withdrawal or disposal revokes previously granted fields. Other tags or consent managers can issue their own Google consent commands outside this adapter's control. A Meta-only marketing choice can continue without this adapter granting Google ad fields on upgrade.

GA4 consumes page and business analytics, Meta consumes marketing conversions with shared eventID/event_id, optional Clarity consumes analytics. Explicit verified purchase only. No automatic API call becomes a business conversion. Dispatch returns per-provider sent/denied/skipped/failed/invalid/dropped outcomes without raw provider errors or response bodies. `skipped` is not an error: the provider was deliberately not called because it has no mapping (`event_mapping_missing`) or the call targeted other consent categories or provider names (`not_targeted`). Sent means adapter completion: provider-side attribution/dedup must be tested separately.

The example-owned `custom_event` schema requires an `action` matching `^[a-z][a-z0-9_]{0,39}$`. That action becomes the GA4 event name, the Meta Pixel custom event name, the Meta CAPI event name, and the Clarity event name. Each configured provider receives the same SDK event ID; GA4 and Meta can include it in their calls, while Clarity's event API takes only a name. Clarity page views use its page/session capture without an explicit event call. The integration mapping tables record predefined and example-event behavior. Consumer mappings explicitly project schema properties and may use a validated string field for the vendor event name. Missing mappings produce `skipped`/`event_mapping_missing` for that consented provider; other providers continue. Meta has no mapping for `remove_from_cart`, `view_cart`, `add_shipping_info`, `refund`, `view_item_list` and `select_item`. Registration rejects duplicates, predefined overrides, passthrough/transform schemas and unknown projection sources.

The shared contracts privacy guard rejects contact-like values in nested validated properties for both predefined and consumer events. It also rejects forbidden raw identity property keys. The contracts reject the entire event when `search_term`, example `custom_event` `action`/`label`/`category`, `lead_type`, or auth `method` contains email- or phone-like text, including common percent-encoded forms. No rejected value appears in provider payloads or diagnostics. This pattern check is a bounded safeguard; hosts remain responsible for avoiding personal data in all event fields.

## Automatic technical flow

Browser once per page: initial page, pathname changes via History API/popstate, fetch/XHR method normalized route status duration failures. Query-only changes produce no automatic page event. Hash-only changes produce no page event unless `trackHash: true` enables `#/` or `#!/` route tracking; ordinary anchors remain ignored. Deduplicate on the resolved route path. Repeated mounting must not duplicate initial pages. Instrumentation doesn't consume response/request bodies, mutate host results, or add trace headers outside configured origins. Existing valid context is preserved. Own patches are restored on stop; other libraries' patches are preserved. The experimental standalone bundle exposes `window.signals`; all categories start denied, no script attribute grants consent, and the host consent banner calls `window.signals.setConsent(...)`.

Standalone declarative product/cart/checkout clicks require explicit item ID, price and currency; cart/checkout also require quantity. Missing or invalid attributes drop the click and emit a diagnostic containing only status, reason and attribute name. No placeholder item, price, currency or quantity is inserted.

Bun once around its fetch handler: incoming request plus explicit signals.fetch outbound requests, concurrent context isolation, route resolver. Bun route-table handlers bypass fallback fetch; passing the declarative routes table through `instrumentBunRoutes` wraps its handlers with their route patterns. No native/global fetch mutation on server. Next uses a browser root provider and host-owned Node OTel registration to capture framework incoming requests; wrap outbound calls with signals.fetch where needed. Existing host OTel providers stay host-owned. Edge not supported.

Server outbound fetch adds trace context to absolute URLs only for exact `traceOrigins` matches. Relative URLs require `traceRelative: true` and a host transport that supports relative fetch; the default is false. Existing trace headers are never replaced.

Default redaction removes query/hash, numeric/UUID/email/long token path segments and recognized ObjectID, Stripe ID and CUID formats. The shared core URL sanitizer removes query strings, fragments and URL credentials from GA4 page metadata and Meta CAPI event-source URLs; attribution parameters are not forwarded. Product slugs containing numbers remain distinct paths. Arbitrary sensitive slugs and order/reference IDs cannot be inferred safely; hosts must supply route templates or exclusions for those paths. Known browser provider telemetry domains excluded; custom collector endpoints require excludeUrls.

## Failure and resource policy

Default core 100 pending events and 5s dispatch deadlines. Custom observer pending work bounded; OTLP default20 requests/2s deadline. Core event overload produces a dispatch diagnostic. Browser observer records beyond the 32-pending bound are dropped silently; they do not create fake event/provider outcomes. No unlimited retry, durability or guaranteed delivery in SDK. Host outbox owns persisted order/payment consent and retry. Business host operations continue on tracking failures.

Third-party scripts load only for allowed provider dispatch and use vendor revocation APIs, with one opt-in exception: with `preloadProviders: true` the browser SDK calls each granted provider's `prepare()` at start and when a category becomes granted, which loads the vendor script without sending an event. Scripts' own DOM/cookie/network behavior is outside SDK payload sanitation; configure masking, automatic-event settings and CSP. Script failure produces failed/dropped outcome. Browser global JS errors and unhandled rejection capture are outside this request-only v1 contract; Next supplemental request-error hook is available.

## Attribution and search sources — 4 November 2026

GA4 page_location keeps only utm_source/medium/campaign/term/content/id, gclid, gbraid, wbraid, msclkid and fbclid (values trimmed, ≤256 chars, no control/quote/angle characters, no @); page_referrer is the referrer scheme and host only. Optional browser attribution: capture location.href plus document.referrer at start; classify gclid/gbraid/wbraid as paid search google, msclkid as paid search bing, utm_medium cpc/ppc/sem as paid search when the source is a search engine else paid other, paid_social, social, email, organic, referral, display-like mediums as paid other, unknown mediums as other; without UTMs use the referrer host tables for organic search, AI search, organic social and referral; fbclid alone is organic social; same-origin referrer without parameters is internal navigation and not a touch; no referrer is direct. Direct never overwrites a stored touch. Persist first/last touch under the configured consent category (default marketing), clear on withdrawal, expire first touch after maxAgeDays (default 90). getAttribution merges memory and storage; clearAttribution removes both. Search console clients validate ISO dates and site identifiers, clamp rowLimit 1–5000 and timeout 1–60s, honour abort signals, normalise rows to engine/query/page/clicks/impressions/ctr/position and never include tokens, keys, URLs or provider bodies in errors. Acceptance: core classification tests, browser consent/persistence/expiry/GA4 payload tests, server request/response/rejection tests, Next lab Playwright landing-source test; live GA4 channel reports and console account data remain unverified.

## Attribution self-check — 4 November 2026

Owner asked whether a CLI should verify the guide's routing and rendering rules across frontend platforms and versions. Decision: no per-framework static checker; the rules are runtime and platform configuration, so the browser SDK exposes `auditAttribution(options)` that any host calls in development. Inputs: optional SDK instance, document, location, performance and expected script hosts. It is synchronous, never throws, performs no network access and retains nothing. Findings with stable ids: attribution-disabled (SDK given without `attribution`), params-dropped-by-redirect (navigation redirectCount above zero, no tracking parameter on the final URL, referrer host is a known search/AI/social host), params-removed-before-capture (navigation entry URL or current URL carries a tracking parameter but getAttribution is empty), canonical-has-tracking-params, csp-blocks-vendor (meta CSP script-src, or default-src when script-src is absent, omits googletagmanager.com for ga4 or connect.facebook.net for meta-pixel, or an expected host), storage-unavailable (localStorage missing or set/remove throws), consent-never-granted (info; configured category denied), multiple-sdk-instances (a start was refused because another instance was active). Browser API adds `isAttributionEnabled()` and `getAttributionCategory()`; core exports `classifyReferrerHost`. Acceptance: jsdom tests per finding and a hostile-input never-throws test; Next lab "Audit attribution" button; Playwright asserts a `?gclid=test` landing has no error findings and an injected tainted canonical yields canonical-has-tracking-params. A header-delivered CSP, CDN cache keys and server-side redirects that keep the query are outside what the page can observe.

## Commerce lifecycle, per-call context and identity — 19 November 2026

Released in 0.1.0-alpha.6. All evidence below is fixture, jsdom, injected-transport or local Playwright; nothing is live-verified.

Events. The 17 predefined events and their GA4, Meta and Clarity mappings are in the [integration guide](../../packages/features/signals/INTEGRATION.md#predefined-event-contracts). A provider with no mapping reports `skipped`; a mapping that fails validation reports `invalid`. Event definitions registered by a consumer cannot use the eight new names or their provider names.

Outcomes. `sent` (adapter completed), `denied` (category not granted), `skipped` (`event_mapping_missing` or `not_targeted`, not an error), `failed`, `invalid` (`event_schema`, `event_mapping`, `track_options`, `event_context`) and `dropped` (capacity or disposed). Hosts whose outbox requires every outcome to be `sent` must also accept `skipped`, and treat `denied` as terminal for that copy.

Per-call options. A server `track` call may supply `consent` (replaces instance consent for that call; not aborted by `setConsent`), `context` (page, GA4 and Meta slices, validated and bounded, never in diagnostics) `categories` (deliver only to those consent categories) and `providers` (deliver only to providers with those names, at most 20; a provider must match both filters when both are given). The browser accepts only `categories` and `providers`; it ignores per-call consent and context. Malformed options return `invalid`. Providers receive only the context slice for their own event family, and the CAPI and Measurement Protocol providers refuse sends whose consent snapshot denies their category.

Identity. `setUser({ id, customerType })` and `resetUser()` forward an opaque key (`^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`) to GA4 and Clarity while analytics is granted. Withdrawal clears it; a later grant restores it. The Meta Pixel receives nothing. Identity is never an event property.

Consent-time page view. With `pageOnConsent`, when analytics or marketing flips from denied to granted while the SDK is running, the browser dispatches one new `page_view` for the current route to only the newly granted categories and only to providers with an event family. A route already viewed under a category is not sent again. Denied events are never queued or replayed. Hosts enabling it remove their own post-consent `page()` call. `landingParams` attaches the landing URL's allowlisted campaign and click parameters to that one analytics hit when the current URL has none; it is off by default.

Attribution read gate. `getAttribution()` returns an empty object while the attribution consent category is denied. The in-memory landing touch is kept and persists on a later grant. `isAttributionCaptured()` reports capture without exposing the touch, and `auditAttribution` uses it.

Provider identifiers. `getProviderIds({ timeoutMs })` returns GA4 `clientId` and `sessionId` and Meta `fbp` and `fbc` from granted providers only, validated, bounded to 50 to 2,000 ms (default 500) and never retained. `fbc` falls back to a value built from the stored `fbclid`.

GA4 page location. The browser sets the GA4 `page_location` and `page_referrer` from the tracked route, so hash routes (with `trackHash`) and an explicit `page(path)` are reflected. Query allowlisting and referrer reduction are unchanged.

Measurement Protocol. `createGA4MeasurementProtocolProvider` sends the event under its GA4 name from the server. It never invents a `client_id`, sends `timestamp_micros` only within 72 hours, defaults both Google ad consent fields to `DENIED`, and keeps the API secret in the request query only, out of errors and diagnostics. With it enabled, the browser purchase is dispatched with `providers` naming every browser provider except `ga4`, so Clarity and the Meta Pixel still receive it, and GA4 `purchase` is server only. The host withholds the browser GA4 copy only when the server copy will actually be sent (secret configured, `client_id` stored, analytics consent recorded); otherwise the browser sends it. GA4 deduplicates purchases by `transaction_id`; `event_id` is informational. A 2xx response means the request was received, not that GA4 accepted or attributed the event.

Meta CAPI. Per-call `context.meta.userData` and `context.meta.eventSourceUrl` replace the option fallbacks. The `eventSourceUrl` option is now optional. No Pixel advanced matching or `external_id` is sent by the browser adapter.

Development warning. With `debug: true`, core calls `onWarning({ code: 'duplicate_event', name })` when the same name and properties repeat within one second without a caller-supplied event ID. It carries no values and never suppresses delivery.

Evidence still required: GA4 DebugView (corrected `gtag` command shape, `user_id`, consent-time attribution, Measurement Protocol) and Meta Test Events (deduplication, `AddPaymentInfo`, `AddToWishlist`).
