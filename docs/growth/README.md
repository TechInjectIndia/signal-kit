# SignalKit adoption kit

These are ready-to-use pilot and maintenance assets. They are not evidence of users, traffic, installations, savings or provider delivery.

The first audience is developers building ecommerce with Next.js or Bun. Start with one real host project, then five external developers. Keep the public description narrow: consent-aware ecommerce tracking with shared typed events and request telemetry.

## First month

Proposed targets: five external installations, two projects still using SignalKit after 14 days, one evidence-backed case study and one external contribution. Stars are a secondary discovery signal, not an adoption measure.

1. Make the current source and quickstart easy to try; resolve npm ownership and release checks before advertising registry installation.
2. Choose one authorized ecommerce project and measure the integration using the [pilot guide](PILOT-GUIDE.md).
3. Recruit five external developers individually, with their permission to record anonymized feedback. Fix onboarding failures before widening distribution.
4. Record observed outcomes in [SCORECARD.csv](SCORECARD.csv) and write an actual story using the [case study template](CASE-STUDY-TEMPLATE.md).
5. Follow the [weekly maintainer routine](MAINTAINER-SOP.md).

The real integration is assigned to the owner’s developer. Five willing recipients, publishing account selection and npm scope access verification remain pending. No invitations or social posts are sent by this kit. Begin with one chosen channel, LinkedIn, then a selected developer community whose rules permit the relevant example. Technical articles can support these posts; avoid repeating the same launch announcement across communities.

The CSV has headers only. Add a row after an actual observation; leave unavailable fields blank. Never copy a target into an observed result. Report source-based trials separately from future registry installs.
